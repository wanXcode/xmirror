# XMirror V1.6 Roadmap

## 版本目标

V1.6 的目标是把 XMirror 从“可用的生产级 MVP”推进到“可持续运营的小型产品”。核心价值仍然聚焦在一件事：稳定地把 X / Twitter 内容保存成长期可访问、可分享、可翻译的镜像页面。

本版本优先解决安全、可维护性、可检索性和可观测性，暂不扩大内容来源。

## P0：发布前必须完成

### 1. 安全与权限
- 所有删除、审核配置等管理操作统一要求管理员 token。
- 管理 token 仅通过 `x-admin-token` 请求头传递。
- 去除运行时 `0777` / `0666` 世界可写权限，目录和 SQLite 使用更小权限范围。
- 生产数据、媒体、日志与代码仓库彻底分离。

### 2. 工程与发布
- GitHub Actions 自动运行 `npm ci`、`npm test`、`node --check server.js`。
- 后续改动默认采用 Issue → branch → PR → review → merge。
- `main` 只接受经过验证的变更。

## P1：V1.6 核心产品能力

### 3. 归档搜索与筛选
目标：历史归档数量增长后仍能快速找到内容。

最小范围：
- 按作者、用户名、正文关键词搜索。
- 按时间倒序查看。
- 支持基础分页。
- 搜索结果继续使用现有短链。

暂不引入 Elasticsearch 等外部搜索服务，优先使用 SQLite 能力验证需求。

### 4. 运行监控与失败统计
目标：能够回答“最近归档成功率怎么样，主要失败在哪里”。

最小范围：
- 归档成功 / 失败计数。
- 按失败类型归类：X API、下载媒体、内容审核、数据库、翻译等。
- 提供简单管理接口或日志汇总。
- 不在本期建设复杂 BI 看板。

### 5. Markdown 导出
目标：让单篇归档可以离开 XMirror 独立保存和进入知识库。

最小范围：
- 单篇导出 Markdown。
- 保留正文结构、原文链接、作者、时间和本地媒体引用。
- PDF 先使用浏览器打印能力，不单独建设 PDF 引擎。

## P2：完成 P1 后再评估

- 批量导入 X 链接。
- 更多目标翻译语言。
- 访问统计页面。
- 管理端批量操作。

## 本期明确延后

- 微信公众号等新内容源。此前线上抓取受出口风控影响，在没有稳定抓取方案前不重新投入。
- 用户账号、订阅、付费体系。当前尚无明确商业化需求，不提前增加复杂度。
- Elasticsearch、Redis、消息队列等基础设施。当前规模优先保持单机和 SQLite 简洁架构。

## 技术债务

`server.js` 当前同时承担路由、数据库、抓取、媒体下载、渲染、翻译和管理接口。V1.6 期间逐步拆为：

- `routes/`：HTTP 路由
- `services/`：归档、翻译、审核业务逻辑
- `repositories/`：SQLite 数据访问
- `lib/`：无状态通用能力

拆分采用渐进方式，每次只迁移一个稳定模块并保留回归测试，避免一次性重构。

## V1.6 完成标准

1. 管理类写操作不存在未鉴权入口。
2. GitHub PR 自动执行测试和语法检查。
3. 运行数据不再被 Git 跟踪。
4. 用户可以搜索历史归档。
5. 能看到基础成功 / 失败统计。
6. 单篇内容可以导出 Markdown。
7. 核心归档、短链、Article、翻译功能回归通过。
