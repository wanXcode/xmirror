## 优先级一：人工审核通过与 SEO 判断不一致

**性质：已复现的实现缺陷。**

`lib/seo-store.js` 的 `assess()` 直接调用原始规则审核器 `moderator.moderateArchivedContent()`，没有读取人工审核服务中与内容指纹及规则版本绑定的有效决定。`lib/seo.js` 又在处理人工 SEO 推荐前，把所有非 allow 状态返回为 `review / moderation_unknown`。

离线使用线上同版源码复现：

1. 一篇合法技术教程因“调教 AI 模型”措辞进入待审。
2. 人工决定 allow 后，正式内容审核服务对相同内容返回 allow。
3. SEO 模块重新检查相同内容，仍返回 `review`、分数 0、`moderation_unknown`。
4. 即使设置 `seo_override='index'`，也不能消除此处的状态分歧。

只读检查发现一条人工 allow、原始规则仍为 review 的记录，但未关联到现有存档；**不能声称当前有多少线上存档已经受影响**。缺陷本身已被独立复现。

修复要求：让内容入口与 SEO 使用同一份有效审核结论，复用内容及版本绑定机制；审核变化后触发对应 SEO 重评。人工内容放行只解除审核障碍，仍需独立通过 SEO 质量判断，不能直接等于进入 sitemap。封禁、删除、拒绝和失效决定仍优先。

验收：同内容人工允许后两个模块认知一致；正文或链接目标改变后旧决定失效；人工拒绝/封禁后 sitemap 与页面 robots 一致降级；全程保持本地规则与人工复核，不向外部模型发送正文。

源码：[seo-store.js](https://github.com/wanXcode/xmirror/blob/b3a93018d948fb072f54bc6f9decf7cf7f98dbc7/lib/seo-store.js#L29)、[seo.js](https://github.com/wanXcode/xmirror/blob/b3a93018d948fb072f54bc6f9decf7cf7f98dbc7/lib/seo.js#L60)、[人工审核接口](https://github.com/wanXcode/xmirror/blob/b3a93018d948fb072f54bc6f9decf7cf7f98dbc7/server.js#L1770)。

## 优先级一：长度规则不能代替搜索价值判断

**性质：原方案与实现共同存在的设计局限。**

原定稿已允许“正文达到 160 个有效单位且元数据完整”独立取得推荐资格。当前实现延续为 `score >= 70 || count >= 160`。规则能检查格式，却不能可靠判断正文是否有信息增量、明确主题、重复灌水或搜索需求。

离线反例：来源、作者、时间等元数据有效，审核允许，正文为 `<p>` 包裹的 `word ` 重复 160 次。线上同版 `seo.evaluate()` 返回：

```json
{"status":"index","score":50,"reasons":["substantial_text","complete_metadata","readable_structure"],"units":160}
```

这证明现有规则会把无意义重复视作充实正文；**不是说网站已经出现该反例内容**。目前 210 条候选中有 26 条分数为 50，依靠长文本条件进入候选；不能直接断言它们质量差，真实纯文字长文也可能很有价值。

改进要求：

- 把机器分数定义成“技术准入和初筛”，不要称为 Google 质量分或已收录状态。
- 加入重复句段、极低词汇多样性、模板占比、正文完整性等可解释的异常信号；边界内容进入 review，避免机械误杀诗歌、代码、列表等格式。
- 从现有候选中选择小规模、有明确主题和实际阅读价值的观察组，人工抽查其可回答的问题、来源可靠性和页面增量价值。
- 结合 Search Console 数据调整推荐范围，不批量撤下现有 210 条，也不简单提高字数或强迫文章配图。

Google 明确警惕缺乏附加价值的抓取转载与规模化低价值内容。稳定访问、媒体保留、阅读增强是产品价值，但不能仅凭这些功能断言 Google 会优先展示镜像副本。自动改写几句、添加关键词或换域名也不能解决这个问题。

源码：[准入条件](https://github.com/wanXcode/xmirror/blob/b3a93018d948fb072f54bc6f9decf7cf7f98dbc7/lib/seo.js#L79)。

## 优先级二：标题机械截断普遍存在

**性质：已量化的页面质量问题。**

当前取正文第一个 H1/H2，否则取整段纯文本，再直接截前 100 个 Unicode 字符；摘要取前 200 个字符。210 条候选中 **158 条标题恰好为 100 个字符，占约 75.2%**。抽查存在在“这一点上，我真的很喜”“非常口”等位置切断句子的情况。

Google 没有统一的 60 或 100 字符硬性标题上限；问题在于标题不够清晰简洁、很多只是正文开头片段。它可能影响主题表达与点击判断，不能由本次检查量化其排名或点击损失。

改进要求：优先真实原文标题；没有标题时选择能独立表达主题的完整句或短语，在词句边界截断；重点页面提供独立可审核的展示标题和摘要字段。元数据与可见 H1 保持语义一致，不改写用户原文，不虚构结论，不堆关键词。

验收：覆盖中文、英文、长标题、无标题、URL 开头、表情、代码等样本；重点观察组逐条检查标题是否忠实表达主题。不要用“所有标题都缩到某个字数”作为质量验收。

源码：[metadata()](https://github.com/wanXcode/xmirror/blob/b3a93018d948fb072f54bc6f9decf7cf7f98dbc7/lib/seo.js#L27)。

## 优先级二：实际搜索效果仍未得到验证

**性质：验收证据缺失，不能直接判为代码故障。**

本次未取得 Search Console 权限，不能确认账号当前是否已经验证。以前的“尚未验证”记录不能替代今天的账号状态。

应检查 sitemap 处理结果、网页索引原因、Google 所选 canonical、自然查询与落地页点击，并把站内 `index` 明确标注为“本站允许收录”，与“Google 已收录”分开。

统计脚本 `https://a.zhxs.me/js/script.js` 实测 200，浏览器存在真实 tracker 函数，因此不能把统计说成已损坏。仍需在正常浏览器与统计后台核对页面访问、自然搜索来源、关键事件与转化是否收到。旧统计域名配置本身不构成失效证据。

建议观察组记录：页面主题、规则版本、入组时间、索引状态、查询、展示、点击、CTR、关键互动。沿用原计划 4–8 周复盘；这个期限是实验窗口，不是收录承诺。先取得基线，再决定是否扩大自动推荐。

未验证身份的 Googlebot User-Agent 日志不作为真实 Google 抓取证据；`site:` 查询也不作为完整索引统计。

## 后续优化，不作为本轮阻断项

- **主题发现与内链：**候选可通过约 11 页 browse 分页到达，目前不是孤儿页问题。210 条中 150 条没有同作者相关推荐；不能因此随机填推荐。后续围绕已经有内容密度的主题做少量精选合集，提供真实说明和上下文链接，避免生成大量空泛标签页。
- **图片语义：**自动 alt 主要重复作者和标题，只能作基础兜底。重点页面应提供图片实际内容的简洁描述。发现一篇候选的正文图片缺尺寸，适合补齐，但不足以认定全站图片故障。
- **性能：**一次未限速浏览器样本中，首页 LCP 约 4.9 秒、文章约 2.7 秒，CLS 很低。这是进一步测量的信号，不是站点真实用户 Core Web Vitals 判定；尚无有效 INP、CrUX 或 Search Console 实地数据。应再用可重复实验与真实用户数据定位，不直接归因。
- **结构化数据：**JSON-LD 存在且可解析不等于符合全部富媒体结果条件，更不保证展示富媒体结果。后续选样本做官方验证，保持字段与实际内容一致。

## 建议下一小版本与验收边界

先做审核结论共享、变更重评、标题摘要完整性，以及基础重复内容异常检测；保留统一管理后台，不另建审核系统。补充能覆盖真实状态变化和上述反例的回归测试。

发布前后验收：人工决定与 SEO 状态一致；内容变更使旧决定失效；无意义重复不自动推荐；合理长文不因无图被误杀；候选页 canonical、robots、sitemap 一致；重点标题可读且忠实原文；保持已确认的首页与页脚布局。

Search Console 与统计后台验证作为独立的效果验收工作，并行推进；在数据未建立前，不把“技术上线完成”表述为“SEO 带量方案全部完成”。

## 官方依据与复核材料

- [Google 垃圾内容政策](https://developers.google.com/search/docs/essentials/spam-policies)：规模化低价值内容、无附加价值的抓取转载。
- [Google 标题链接](https://developers.google.com/search/docs/appearance/title-link)：描述性、简洁、忠实内容，没有固定字符数上限。
- [Google 规范网址](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)：canonical 与 sitemap 是信号，最终规范页由 Google 选择。
- [Google 可抓取链接](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)：HTML 链接与有意义的上下文。
- [Google 分页](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading)：可访问分页链接及各页独立 canonical。
- [Plausible 自定义事件](https://plausible.io/docs/custom-event-goals)：事件目标配置与后台接收需要单独验证。
