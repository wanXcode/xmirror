# XPut v1.7.0 长文章渐进翻译需求

- 基线版本：v1.6.1
- 计划版本：v1.7.0
- 日期：2026-09-26
- 状态：v1.7.0 实现稿；后端任务接口与前端渐进显示已落地，待本地验收后发布

## 1. 背景与目标

现有翻译采用整篇同步响应：用户点击后，服务端逐批翻译，全部完成才返回和缓存。任何一批超时都会导致整篇失败，用户无法阅读已完成的部分。

实际案例：`https://xput.app/Bmo0M6` 共 58 段、7,044 个正文字符。现有每批 30 段的请求在主模型上等待 55 秒仍未返回，超过生产环境 40 秒限制；同模型单段约 9.8 秒成功，备用模型同批约 15.4 秒返回内容。对照结果证明当前主模型与批量策略的组合不稳定，不代表备用模型已通过完整译文质量验收，也无法确定供应商内部延迟原因。

本版目标：用户尽快读到开头译文，长文逐步完成；局部失败可恢复，离开页面不丢进度，同一篇文章不重复翻译。

## 2. 范围

包含：存档正文中英文翻译、后台任务、按文字量分批、逐批保存、渐进显示、超时重试与备用模型、失败续翻、共享缓存、进度及错误提示。

不包含：视频字幕流程改造、图片 OCR、更多目标语言、用户选模型、手工编辑译文、翻译历史版本界面、通知推送。继续沿用现有原文／译文阅读入口，不引入新的阅读模式。

## 3. 用户流程与页面行为

1. 点击“翻译为中文／英文”后，立即反馈“正在准备翻译…”，创建或取得现有任务。
2. 排队时显示“正在排队，完成后会自动显示”，不展示无法保证的队列名次或剩余分钟数。
3. 优先处理文章开头。首批完成即显示对应译文，后续按原文顺序更新，不等整篇完成。
4. 翻译视图保持标题、段落、列表、引用和媒体的位置关系。未完成部分显示原文并标注“待翻译”或“翻译中”，不留大片空白，也不把原文冒充译文。
5. 工具栏显示“已翻译 12 / 58 段”。分母为原始可翻译段落数；内部拆分的子段不增加分母，原段所有子段完成才计为完成。
6. 局部失败显示“已翻译 55 / 58 段，3 段未完成”和“重试未完成部分”。失败段保留原文，其他批次继续执行。没有任何译文时显示明确失败原因和重试入口。
7. 全部段落成功后才显示“翻译完成”。已有全部译文时直接展示缓存；已有部分译文时立即展示并恢复任务状态。
8. 切换原文不取消任务；切回译文展示最新进度。刷新或关闭页面后后台继续，重新访问恢复已完成内容。重复点击、多个标签页及多人同时访问共用同一任务。
9. 更新译文不主动跳转到页首、不抢焦点。进度通过无障碍状态区域温和播报，不逐段连续打断读屏。

## 4. 任务与结果规则

### 4.1 任务身份与状态

任务按“存档 ID＋目标语言＋源正文指纹＋翻译策略版本”识别。相同任务只有一个有效执行者，重复请求返回现有任务；不能仅靠浏览器防重复点击。

| 状态 | 含义 | 用户动作 |
| --- | --- | --- |
| 排队中 | 等待执行资源，可能已有历史部分译文 | 可阅读原文或已有译文 |
| 翻译中 | 正在处理未完成内容 | 查看进度、切换原文 |
| 全部完成 | 所有段落均保存了有效译文 | 阅读译文 |
| 部分完成 | 本轮执行结束，仍有失败段落 | 重试未完成部分 |
| 失败 | 本轮结束且无有效译文 | 根据错误原因重试 |

执行中的暂时失败不立即把整篇标记为终止状态；其他可处理批次继续。全部完成、部分完成、失败为本轮终态。重试后进入排队中，保留成功段落。

### 4.2 分批与调度

- 同时限制每批字符量与段落数，不再只按 30 段切分。建议首批不超过 500 字符／3 段，后续每批不超过 1,500 字符／8 段，以先达到的限制为准；字符计数覆盖中英文，不按字节计。
- 单段超过上限时优先按句子边界拆分，必要时按字符安全切分；最终拼回原段，保持顺序，不截断或漏翻。
- 提供文章标题、目标语言和必要的上下文提示，降低分批造成的术语不一致；上下文也应计入请求预算。
- 先调度首批，后续以有限并发执行；建议全站正文翻译同时调用上游不超过 3 个，同一任务不超过 2 个。不同文章公平调度，长文不能长期占满资源。
- 上述数值均可配置，发布前按真实模型延迟与质量调整；不得通过无上限并发提高表面速度。

### 4.3 保存、恢复与兼容

- 每批验证成功后立即持久化，不等整篇完成。页面读取已保存结果；连接断开不丢失后台成果。
- 保存源段索引及子段映射，异步完成顺序不能改变展示顺序。
- 服务重启后恢复未完成任务。通过执行租约／等价机制避免同批重复执行及过期结果覆盖新结果。
- 源文改变后创建新任务，旧指纹译文不能混入当前页面；旧任务不再为当前文章浪费执行资源。
- 现有完整译文缓存经源指纹、段落数量及有效性校验后复用，不要求历史文章全部重翻。旧翻译入口保留兼容，新增任务接口不依赖长连接存活。

## 5. 失败恢复与结果质量

- 超时、网络错误、429 和上游 5xx 视为可恢复故障；按原因退避，429 遵循 Retry-After。主模型超时可切换经验证的备用模型，不再仅在“模型停用”时切换。
- 每个批次默认最多 3 次上游调用，覆盖主模型、重试和备用模型；正文策略只允许切换到预先配置并审核成本的模型。
- 返回格式异常时允许缩小批次再试。单篇整轮上游调用总数建议上限为初始批次数的 4 倍，覆盖拆分和重试，避免递归无限消耗。达到上限后保留成果，进入部分完成或失败。
- 鉴权失败、余额不足、配置错误不反复自动重试，应暂停相关供应商请求并记录运维告警。用户看到“翻译服务配置异常，请稍后再试”等可理解信息，不暴露密钥或供应商原始响应。
- 一批成功必须满足：结果能解析、条目与输入正确对应、每项非空、没有明显的错误说明或截断。格式或数量不符不能补原文并计为成功。
- 链接、人名、代码等可能无需翻译，不以“与原文相同”作为唯一失败依据；验收需人工检查正文是否实际翻译及有无遗漏。
- 重试只提交失败或未完成部分。重复重试请求合并；成功段落不重复计费。异常中断造成的极少量上游重复调用需记录，不承诺外部服务层面的严格一次执行。

## 6. 限制与文案

建议单篇最多 100,000 个可翻译字符、1,000 个原始段落。超过任一限制时在创建任务前说明“文章超出当前翻译上限”，不静默只翻前半篇。限制值可配置，现有译文仍可阅读。

新任务创建和手动重试需限流；查询进度不复用翻译创建配额。站点队列达到容量上限时明确提示繁忙，不能接受后永久排队。排队和执行超时需有终止／恢复规则，开发前确定可配置阈值并覆盖测试。

| 情况 | 展示要求 |
| --- | --- |
| 单批超时，正在恢复 | “部分内容响应较慢，正在重试…”；保留进度 |
| 局部恢复失败 | “还有 N 段未完成，可重试”；提供操作 |
| 浏览器查询进度失败 | “暂时无法获取进度，正在重新连接…”；不能误报后台任务失败 |
| 全站繁忙或访问过频 | 提示稍后再试，提供合理的重试间隔 |
| 无可翻译正文 | 明确说明；不创建空任务 |

## 7. 性能、可观测性与隐私

- 创建／取得任务接口不等待翻译完成，正常服务负载下目标 p95 小于 2 秒。
- 在队列空闲、上游健康的验收环境中，点击至首批译文可见目标 p95 不超过 15 秒；这是待实测指标，不向用户承诺固定完成时间。
- 页面优先使用短轮询或等价可恢复机制；断线重连读持久化状态，隐藏页面降低查询频率。传输可增量获取，避免每次重复下载整篇。
- 记录任务 ID、存档 ID、源指纹、批次索引、字符数、模型、排队和调用耗时、尝试次数、错误类别及结果校验情况。不得记录 API Key；默认不在日志记录正文与译文。
- 统计首批可读耗时、整篇完成率、部分失败率、超时率、缓存命中率和上游调用量，用于调整批次与模型。

## 8. 验收标准

| 场景 | 必须满足 |
| --- | --- |
| Bmo0M6 真实案例 | 先显示首批，最终 58 / 58 段完成；核对顺序、结构和遗漏；存在有效整篇缓存 |
| 短文和长文 | 覆盖 1 段、58 段、200 段及接近长度上限的文本；首批无需等待全文 |
| 超长单段 | 自动拆分并完整拼回；进度仍按原段计数 |
| 中译英与英译中 | 两种方向分别完成，缓存和任务不串语言 |
| 主模型超时 | 故障注入验证有界重试／备用模型生效；用户能继续读已完成内容 |
| 单批持续失败 | 其他批次继续，终态为部分完成；重试仅执行未完成部分 |
| 无效 JSON、少段、空值、截断 | 不标成功、不写入完整成功缓存；有限拆分恢复或明确失败 |
| 刷新、离开、服务重启 | 任务和已有译文可恢复，不从头重做 |
| 多人／多标签重复点击 | 同一身份只存在一个活动任务，不重复调度同批 |
| 源文变化 | 不展示旧指纹译文，不接受旧任务迟到结果覆盖 |
| 队列拥堵、429、鉴权异常 | 分别展示正确状态，重试有上限；短任务不被长文长期阻塞 |
| 移动端及辅助功能 | 页面可读，更新不主动跳顶；按钮状态和进度可被读屏识别 |
| 旧缓存及旧入口 | 已成功译文可复用；旧页面不会因接口迁移失效 |

实时供应商测试用于验证可用性与质量；超时、重启、失败恢复等用可重复的故障注入验收，不能以一次偶然成功替代。

## 9. 发布与回滚

本版作为 v1.7.0 独立实现与评审，已完成应用版本号和静态资源版本升级。先完成状态与缓存兼容测试，再在生产验证指定文章及短文；上线后观察超时率、部分失败率和上游请求量。

数据结构采用可向后兼容的新增方式，保留原完整译文缓存。回滚前停止新任务调度，再切换旧代码；保留新增任务与部分译文数据，不用旧数据库快照覆盖上线后的用户存档。回滚恢复旧翻译行为，渐进翻译和未完成任务恢复需待再次启用新版。
