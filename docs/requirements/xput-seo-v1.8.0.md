# XPut v1.8.0：自动收录与 SEO 基础

状态：开发版本；承接 `xput-seo-baseline-v1.0.md` 的第一阶段。对应 GitHub Issue #43。

## 本版本交付

- 启动时幂等追加 SEO 状态、分数、原因、检查时间、状态变更时间、规则版本、内容哈希、人工覆盖和封禁字段；历史记录默认 review。
- 存档完成、重复提交/修复、视频状态变化、翻译缓存写入后自动评估；暂时错误保留 review，不影响页面继续阅读。
- 规则见 `config/seo-rules.json`。160 内容单元的纯文字页面可以通过，不强制存在图片或文章标题。分值是本产品的实验门槛，不是 Google 标准，也不能验证搜索需求或原创性。
- 风险/封禁、站内完全重复、无效来源优先排除；审核不确定保持 review。管理员可以为有实际价值的短内容做例外，但不能用“推荐”解除已设置的封禁；必须先单独解除封禁。
- 审核沿用当前文字/域名/作者规则，并独立于“允许新增存档”开关。它不能自动识别所有图像风险、版权归属、事实真伪或敏感信息；投诉通过后台封禁处理，访问删除仍使用已有删除功能。
- 新增 `/robots.txt`、`/sitemap.xml` 和超 49,999 条时的分片索引。sitemap 不读取正文，不调用上游；只列 index 且未封禁的短码与首页。没有可靠内容修改时间时不输出 lastmod。
- 普通 API/admin/demo 返回 X-Robots-Tag: noindex，允许抓取以读取该标签。会产生存档操作的 `/api/archive/` 禁止抓取，这不被当成去索引保证。
- 首页原始 HTML 包含最近 10 条公开记录，继续保留现有本机记录、无限滚动、日期等交互。增加 `/browse` 作为合格内容分页导航，页码各自 canonical，空的越界页返回 404。
- 旧 HTML URL 与别名短码 301 到规范短码；删除记录不再通过残留静态 HTML 泄漏。数据库错误返回 503。
- 修复图片数组解析，分享图使用存在的本地图片绝对地址或品牌图。清洗标题/摘要，区分原帖发布时间和保存时间，内页输出内容语言；不改正文、图片、视频、译文段落和来源中转行为。
- 管理页新增最近 100 条收录记录筛选及自动/推荐/不推荐/封禁/解除封禁操作，复用现有 token 鉴权。完整历史批量处理使用 CLI。

## 判定说明

1. 先过滤封禁、审核拒绝、完全重复、无效来源；审核未知则 review。
2. 人工 noindex 优先；非空正文的人工 index 例外须仍通过上面的门槛和完整元数据检查。
3. 作者、账号和有效原帖时间缺失时 review；少于 40 内容单元暂不推荐。
4. 依赖视频且文本少于 160、视频尚未完成时 review；充分文字不会因为一个附属视频失败而被拒绝。
5. 正文达到 160 单元可自动推荐；其余按规则评分。自动推荐可用 `SEO_AUTO_INDEX=false` 暂停，保留已有决定，只有后续重评会改变状态。

内容单元：剔除 HTML、URL、装饰符号，拉丁语按词、其他文字按 Unicode 字母计数。哈希包含正文、链接目标、图片和视频身份；只作站内完全重复检测，不声称已识别互联网范围的抄袭。隐藏的翻译缓存不自动当作 Google 可见新增内容加分。

`seo_status` 是最终持久化状态，页面 meta 与 sitemap 同源；review/noindex 页面继续正常访问。封禁/删除后站点地图和内页不缓存旧决定。SEO noindex 本身不等于访问封禁。

## 历史评估与发布

部署前必须保存数据库快照，并先在快照上预评估。工具默认只读，不迁移 schema、不写审核日志：

```sh
DATA_DIR=/path/to/copied-data SQLITE_PATH=/path/to/copied-data/db.sqlite node ops/evaluate-seo.js --limit=100
```

输出 ID、短码、状态、分数、规则原因和最后 ID，不输出正文或凭据。先抽查中英长文、短文、图片/视频帖子和风险边界。通过后在已备份的目标数据库分批应用：

```sh
DATA_DIR=/path/to/data SQLITE_PATH=/path/to/data/db.sqlite node ops/evaluate-seo.js --apply --limit=100
DATA_DIR=/path/to/data SQLITE_PATH=/path/to/data/db.sqlite node ops/evaluate-seo.js --apply --after-id=123 --limit=100
```

`after-id` 使用上一次输出的 lastId；不应并行运行多个 apply。CLI 通过比较源内容/覆盖状态避免覆盖并发修复，检测到变化会失败，需要重新运行该批。重复检测保留较早记录，较早记录删除或修复后需重评同组记录。

发布必须遵循 CONTRIBUTING：PR/CI/Review/合并，服务器从精确 main SHA 经 ops/deploy.sh 发布并验证。首次迁移会使未评估历史页输出 noindex；因此应在发布窗口先完成备份、预评估及选定批次 apply，再切换流量，避免将整库 review 状态长时间暴露给爬虫。未纳入首批的页仍可正常阅读。

暂停扩量：设置 SEO_AUTO_INDEX=false 并重启，之后的新合格候选保持 review。已 index 页面如需撤回，使用后台不推荐/封禁或对明确批次重新评估；不要因 Search Console 的“已抓取但未编入索引”单一状态就把全部页面 noindex。

代码回滚保留追加字段即可，不做破坏性 down migration。但旧代码默认 index，无法执行本版封禁策略；存在下架要求时先在代理层维持相关 URL 的限制，优先修复本版，不能盲目回滚以恢复全部 index。

## 本版本验收与后续边界

本地必须通过：规则/迁移/状态一致性测试；真实 HTTP 的 robots、sitemap、SSR、分页、301、删除404、管理员鉴权；原有存档、图片、翻译、字幕测试；语法检查。

上线后独立验证：Cloudflare 的 robots 是否覆盖应用、真实 Googlebot 的访问、Search Console 站点验证与 sitemap 提交、真实分享卡片、移动端性能与流量归因。不能用本地 HTTP 或模拟 User-Agent 替代 Google 实际抓取证明。

后续版本：独立语言 URL/hreflang、类型准确的结构化数据、相关主题推荐、模型辅助质量判断、按主题的搜索增长实验。DNS/www 与 Search Console 属于运维配置，不在本次代码里猜测修改。首期观察 4–8 周的非品牌展示、点击、有效落地页及从阅读到存档的转化，再迭代规则。
