# XPut v1.9.5 审核误拦截修复与上下文复核

日期：2026-09-28。基线：GitHub main v1.9.4。关联：Issue #59。

## 目标与边界

针对最近78篇去重拒绝样本，减少由作者姓名、通用链接、普通推广词和粗口造成的色情误判，同时让复合成人标签进入复核。保留原平台敏感标记、已确认账号与成人平台封禁，不批量放行历史记录，不重新发布存档。当前复核仅覆盖文本，不能宣称审核过图片、视频或目标外链。欺诈等其他风险不等同色情，语义不确定则交人工。

## 判定流程

正文去除HTML结构、脚本和裸URL后匹配；姓名不参与正文词命中，账号仅用于明确黑名单。Telegram不再全域封禁，普通营销词不加分；同一词不再关键词与正则累计分数。明确违规规则拒绝；模糊词和完整成人标签产生review信号。

无疑点立即通过；明确违规拒绝；模糊信号等待人工复核。本版不调用外部审核模型，不向模型供应商发送正文，无新增供应商配置或密钥。既有用户主动翻译功能不属于本次审核流程。

管理员重审每分钟最多10次，仅重新获取来源并运行本地规则；不下载媒体，不自动创建公开存档。来源获取失败不视为通过，人工决定不会被重复提交覆盖。

## 数据与恢复

共享数据新增 `data/moderation-reviews/<SHA256>.json`，用临时文件原子替换，正文快照文件权限0600。ID绑定规范推文URL、作者、去标签后正文（保留文本URL）、链接目标、规则版本；图片本地路径不参与文本指纹。人工决定仅覆盖文本版本，规则升级或正文变化需重审；不覆盖原平台敏感标记。

保存判定、正文、命中证据、更新时间与人工理由，追加审核事件日志。人工决定持久化，重启保留历史待复核。文件仅服务端保存，不进入公开静态目录。长期历史清理/保留期限由后续运营策略确定，不在本版自动删除证据。

## 接口和交互

- 收录接口新增409 `CONTENT_MODERATION_PENDING`及422 `CONTENT_MODERATION_REJECTED`；主页中英文提示准确区分待复核、拒绝和网络错误。
- 管理日志按推文数字ID合并后筛选，预检不覆盖正文决定。保留原始JSONL历史事件；旧日志规则版本显示未知，不推测。
- 管理员POST `/api/admin/moderation/recheck`重新拉取指定原文，仅审核不下载媒体、不创建存档。来源失败明确告知，不视为通过。
- GET/POST `/api/admin/moderation/reviews/:id`查看正文、人工通过/拒绝/reset；理由必填≤500字。只允许管理员头部认证，响应no-store。
- 后台正文以textContent呈现，禁止执行原文HTML。人工通过后用户仍需重新收录，不自动公开。已存在存档的可见性继续由原有封禁/删除入口管理。

## 验收与发布

必须通过姓名/URL/技术术语/普通营销/粗口误杀对照、明确违规与复合标签对照、人工决定持久化、重复提交、真实HTTP鉴权及日志聚合测试。

离线回放78篇去重样本：64篇正文可获取，14篇无法获取不计为通过。40篇文本误判中新规则39篇通过、1篇交人工；17篇明确成人文本中10篇拒绝、7篇交人工，无直接放行。其余7篇存在其他风险或上下文疑点；本版不宣称覆盖全部欺诈、图片或视频风险。没有执行历史正文外传验收。

通过GitHub PR与CI后按精确提交部署，保留shared数据与数据库快照。回滚旧release恢复旧规则，复核文件留存；无需数据库回迁或环境变量变更。不得把旧规则回滚描述为继续保有所有误杀修复。
