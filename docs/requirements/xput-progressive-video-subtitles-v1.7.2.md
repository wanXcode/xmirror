# XPut v1.7.2 视频增量字幕需求

- 基线版本：v1.7.1
- 计划版本：v1.7.2
- 日期：2026-09-26
- 状态：已实现，待发布

## 1. 背景与目标

当前视频字幕流程需要先把整条视频按 60 秒切片，逐片完成语音识别，最后才生成完整 WebVTT。长视频在播放器中长时间只能看到“识别中”，中文字幕还要等待英文识别全部完成。

本版改为增量字幕管线：优先复用已有字幕；没有已有字幕时，以短音频片段并行识别，识别一片就翻译一片并追加到播放器。用户应先看到视频开头的字幕，后台继续补齐并在最后做整段校正。

## 2. 范围

包含：视频已有字幕探测、12 秒音频片段、片段级并行识别、片段级翻译、可追加 WebVTT、播放器增量刷新、字幕进度、任务恢复、失败重试和最终校正。

不包含：直播级实时字幕、浏览器端采集麦克风、用户手工编辑字幕、更多目标语言、字幕烧录到视频、改变现有视频下载流程。

## 3. 用户流程

1. 视频下载完成后显示播放器和 CC 菜单。
2. 用户选择 English 或简体中文。
3. 系统立即创建或复用字幕任务；若已有可用字幕，直接加载。
4. 没有可用字幕时，先显示“正在准备前几句字幕…”。
5. 第一批片段完成识别和翻译后，播放器加载已生成字幕，并显示“已生成至 00:12”。
6. 后续片段完成后自动追加，用户无需刷新页面。
7. 全部片段完成后显示“字幕已完成”；后台可继续执行最终校正。
8. 片段失败时保留已有字幕，显示失败片段范围和重试入口，不影响视频播放。

## 4. 处理管线

```text
已有字幕探测
  ├─ 有：下载/解析字幕 → 翻译 → 加载
  └─ 无：ffmpeg 抽取 12 秒片段（重叠约 1 秒）
                  ↓
          最多 3～4 片并行语音识别
                  ↓
          每片识别完成即翻译
                  ↓
          按时间顺序写入临时 WebVTT
                  ↓
          播放器自动刷新已完成部分
                  ↓
          全部完成后整段校正并替换
```

片段结果必须携带 `segment_index`、`start`、`end`、源文本和译文。异步完成顺序不得改变字幕时间顺序。重叠片段产生的重复文本应在合并阶段去重。

## 5. 状态与接口

字幕轨道状态保留现有状态，并增加增量字段：

- `queued`：等待处理
- `transcribing`：正在识别
- `translating`：正在翻译
- `partial`：已有部分字幕可播放
- `completed`：整条字幕完成
- `failed`：本轮无法继续，但可重试

`GET /api/posts/:id/subtitles` 返回：

- 当前状态和百分比；
- 已完成片段数与总片段数；
- 已生成到的视频时间 `covered_until`；
- 当前可加载的临时或最终 `src`；
- 错误信息和可重试状态。

`POST /api/posts/:id/subtitles` 保持幂等。重复选择同一语言只返回现有任务，不重复识别或翻译已完成片段。

## 6. 播放器交互

- 选择器继续提供“关闭字幕 / English / 简体中文”。
- `partial` 状态允许加载已生成字幕，不再禁用语言选项。
- 轮询发现新版本字幕后刷新 track，保持当前播放位置和播放状态。
- 状态文案示例：
  - “正在准备前几句字幕…”
  - “已生成至 01:24，后续字幕继续处理中”
  - “字幕已完成”
  - “第 03:00–03:12 段生成失败，可重试”
- 字幕生成失败不阻止视频播放，也不自动跳转页面或抢焦点。

## 7. 性能目标

- 首段字幕目标：上游正常且队列空闲时，选择语言后 15 秒内可见。
- 片段长度：默认 12 秒，可通过环境变量调整。
- 同一视频同时处理 3～4 个片段；全站并发受独立上限控制。
- 不重复上传或识别已完成片段。
- 页面轮询不得每次下载无变化的完整字幕；使用版本号或 ETag 判断更新。

## 8. 失败与恢复

- 单片段超时、网络错误、429 和上游 5xx：有限重试并保留其余结果。
- 鉴权、余额和配置错误：停止重复重试，展示明确错误。
- 服务重启后恢复 `queued`、`transcribing`、`translating` 和 `partial` 任务。
- 过期任务不得覆盖更新版本的片段结果。
- 最终校正失败时保留增量字幕，状态仍可播放并允许稍后重试。

## 9. 验收标准

| 场景 | 必须满足 |
| --- | --- |
| 34 秒短视频 | 首段字幕先出现，随后补齐，不等待整条完成 |
| 38 分钟长视频 | 进度持续增长，已完成部分可播放，短视频不会被其长期阻塞 |
| 中英文字幕 | 英文识别完成一片后，中文对应片段可独立翻译 |
| 刷新页面 | 已生成部分立即恢复显示，任务继续执行 |
| 片段失败 | 其他片段继续，视频仍可播放，支持重试失败片段 |
| 重复点击 | 同一视频和语言只有一个活动任务 |
| 完成校正 | 最终字幕顺序、时间轴和重复文本正确 |
| 旧字幕缓存 | 已完成旧字幕仍能直接加载，不被新流程破坏 |

## 10. 发布与回滚

先完成本地单元测试、模拟上游延迟和失败恢复测试，再用短视频验证线上首段字幕，最后观察长视频增量进度。发布保留共享数据和旧 release；若回滚，旧版本仍可读取已存在的最终 WebVTT，未完成增量任务等待新版恢复。
